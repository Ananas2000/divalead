# Проверки и сборка v58

Для использования в FL Studio Python и компилятор не нужны. Готовая Windows x64 DLL находится в корне комплекта; требуется только установленная Diva для живого синтезатора. Замороженные WAV работают без Diva.

## Пересобрать эффект

Все нужные C-файлы и заголовки находятся в `analysis/`. На Windows с MinGW x64 из корня комплекта:

```sh
gcc -O3 -shared -static-libgcc -Wl,--no-insert-timestamp -o Diva_Lead_Finish_v58_WIP_x64.dll analysis/lead_finish.c -lm
```

На Linux используется такой же вызов с `x86_64-w64-mingw32-gcc`. В полном checkout репозитория также есть `diva-lead/tools/build_finish.py`:

```sh
python diva-lead/tools/build_finish.py diva-lead/v58-wip --compiler x86_64-w64-mingw32-gcc --image-base 0x268a60000
```

Windows DLL импортирует только `KERNEL32.dll` и `msvcrt.dll`. В ней экспортируется `VSTPluginMain`; собственный ID — `0x444c3538`, два параметра. Лицензионная Diva и её бинарный файл в комплект не включены.

MinGW автоматически выбирает preferred image base по пути выходного файла. Поэтому для побайтовой пересборки этим же компилятором указан `--image-base`; без него DLL остаётся рабочим, но содержит другие адреса релокации. В ручную команду gcc для такого сравнения добавь `-Wl,--image-base,0x268a60000`.

## Независимая проверка

В этой среде использовались Python, gcc и версии пакетов из `analysis/requirements.txt`. Из корня комплекта:

```sh
python -m pip install -r analysis/requirements.txt
python analysis/verify_spectral.py --fixtures
python analysis/verify_release.py
```

Первый скрипт сверяет коэффициенты C и JSON, проверяет 12 произвольных входов без MIDI на 44,1/48/96/192 kHz, причинные префиксы и спектральную фикстуру. Второй проверяет полный расчёт из **собственной сохранённой NEW-базы** этого источника, WAV, MIDI и комплект. Он не объявляет создание этой базы заново из пустой среды. NEW-база заново построена из сырого Diva-рендера с изменёнными velocity и отдельно проверена при этом подборе; её точные байты включены в `verification/NEW_independent_base.wav`.

`analysis/vst_program_probe.c` — проверка Windows VST2 API: имя/ID, параметры, состояние, программа FXP, тишина и PDC на четырёх частотах. Она компилируется MinGW с `-I analysis`. Фактические результаты находятся в `verification/Windows_VST_program_probe.json`.

Компенсация PDC полного WAV снимает 12 416 сэмплов задержки. Короткое сравнение дополнительно использует прежнее внешнее выравнивание и монтаж референса; они не зашиты в DSP. В A/B применяется один общий RMS-множитель к нашему фрагменту, без поканальной или понoтной коррекции. Готовый `REFERENCE_EDIT` совпадает со вторым фрагментом A/B по декодированным сэмплам.

Загрузка DLL и обработка проверялись Windows-хостом под Wine. GUI FL Studio не запускался; его автоматическое восстановление состояния в `.flp` здесь отдельно не проверялось. Это WIP, не заявление о точном совпадении звука.

## Повторить сырой источник

`analysis/replay_source.py` принимает явные пути к Wine, Wine prefix, Wine DLL path, пользовательской Diva, собранному `diva_source_render_host.c` и выходной папке. Он сравнивает все входящие события, 281 параметр и декодированные сэмплы с комплектом. Флаг `--three-held` выбирает отдельный трёхнотный пресет. Оба режима проверены в этой среде; другая версия Diva может не дать побитового совпадения. `--help` показывает аргументы.
