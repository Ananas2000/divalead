# После получения Chorus, Stereo Shaper и QuickFontCache

Перенос на штатные эффекты **ещё не выполнен**. Сейчас нужен один
подтверждённый загрузчиком служебный файл: **`dsp_ippv2_x64.dll`** из `Shared`
той же установки FL Studio. Эффекторы уже получены.

## Проверки новых DLL

Все три новых файла проверены как PE64. Их размеры, SHA256 и импорты сохранены
в `diagnostics/new-three-DLL-inspection.json`.
QuickFontCache теперь загружается. Затем он запрашивает
`dsp_ippv2_x64.dll` и `freetype_x64.dll`.

FreeType удалось собрать из открытых исходников FreeType 2.13.3, commit
`42608f77f20749dd6ddc9e0536788eaad70ea4b5`. Собранная DLL загружается в Windows
через Wine, содержит все 14 функций FreeType, найденных в запросах QuickFontCache,
и действительно загружает TTF и отрисовывает символ. Повторная сборка через
сохранённый скрипт тоже прошла, после неё функциональная проверка повторена.
Это библиотека шрифтов; алгоритмы звуковой обработки не заменялись.
Сборка не является исходным бинарным файлом FreeType из FL Studio.

Chorus, Stereo Shaper, Parametric EQ 2 и Maximus отдельно проверены с этими
зависимостями. Во всех четырёх случаях загрузчик сообщает об отсутствии
`dsp_ippv2_x64.dll`; происходит вызов нулевого указателя при инициализации
QuickFontCache. До `CreatePlugInstance` и обработки аудио выполнение не дошло.
Сохранены журналы с модулем и смещением исключения. Последующие ошибки не
объявляются заранее устранёнными.

Имя `FruityPlug_x64.dll` найдено среди строк файлов, но отдельная зависимость
от этого файла при проверках **не подтвердилась**. Его загрузка не запрашивалась;
просить этот файл сейчас оснований нет.

## Точный эталон переноса

Последний полный опубликованный комплект — `v83-wip`. Эталон:
`diva-lead/v83-wip/Diva_Lead_v83_FULL_180BPM.wav`.
Это полный сигнал после Finish, с компенсацией его задержки. Отдельно сохранён
путь к версии для сравнения с исходным референсом —
`Diva_Lead_v83_REFERENCE_EDIT.wav`.

Замороженный исходник Diva заново пропущен через настоящий Windows DLL Finish
v83. Результат после компенсации задержки совпал с полным опубликованным WAV
**точно по всем отсчётам float32: максимальная ошибка 0, RMS разности 0**.
Совпадение подтверждено и для файла с ещё не компенсированной задержкой.
Это воспроизводимость старого результата, а не готовность штатной цепочки.
Трёхнотный MIDI, пресет Diva и оригинальный референс зафиксированы SHA256.

`compare_to_v83.py` проверяет будущий результат без автоматической подгонки
громкости, времени или нот. Сдвиг разрешён только на явно указанную задержку
реальной цепочки. Скрипт отдельно сообщает точное совпадение float32 и
остаточную разность. Контрольная проверка старого Finish даёт ноль; сухой
исходник Diva даёт ненулевую ошибку. Сам скрипт не подтверждает происхождение
переданного ему WAV — для штатной цепочки дополнительно нужен реальный рендер.

## Задержка и требование полного совпадения

Старый Finish при 48 кГц сообщает 12416 сэмплов задержки, то есть 258,67 мс.
Дополнительный тест настоящего DLL с импульсом показал предзвон в ответе,
если вычесть из него всю эту задержку. При пороге `1e-6` от пика первый
обнаруженный отсчёт находится за 7319 сэмплов до входного импульса; максимальная
амплитуда до импульса — около 0,04678 при амплитуде входа 0,1.

Для произвольного живого входа такой отклик нельзя получить с нулевой
задержкой: потребовалось бы заранее знать будущий сигнал. Тест не оценивает
слышимость отличий и ещё ничего не говорит о качестве штатной цепочки.
Результат переноса должен быть проверен отдельно; обещать его тождественность
заранее нельзя. Приближённый перенос готовым не объявлен.

После добавления `dsp_ippv2_x64.dll` в рабочую папку хоста нужно повторить
загрузку, проверить интерфейс, реальные параметры, состояние и обработку
эффекторов, собрать штатную цепочку, измерить её задержку и сравнить её WAV
с эталоном v83. После подтверждения переноса продолжается подбор к исходному
оригиналу, только с тремя удерживаемыми нотами. Старые Finish-подборщики пока
приостановлены; все прежние релизы и лучший проверенный результат сохранены.

## Повторение сборки FreeType в облаке

Копировать скрипты в `/tmp/divalead-native-effects`, затем выполнить там:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  /workspace/.venvs/divalead/bin/python -B build_freetype_for_host.py
```

Скрипт закрепляет commit FreeType и CMake 3.31.6 и использует уже подготовленный
компилятор MinGW. Для Windows-ресурсов применяется обёртка windres с правильным
целевым препроцессором; первоначальные ошибки сборки ресурсов устранены.
Исходники и лицензия FreeType доступны в его официальном репозитории;
пользовательские DLL Image-Line в GitHub не публикуются.
