# Рабочий обход захвата FL Studio — 22 октября 2026

**Визуальный доступ к видимому окну FL Studio восстановлен через отдельный
локальный захват. Штатный Windows.Graphics.Capture в Computer Use остаётся
неисправным. Файлы установленного Codex не изменялись.**

## Что установлено

Windows 10 Pro, сборка 19045. Codex 26.1016.61520, build 21421, prod.
Встроенная проверка обновлений вернула `up_to_date`.
Штатные список окон, активация и чтение UI Automation работают.
Захват FL возвращал `FrameArrived timed out` и `window capture timed out`;
контрольный захват Проводника также не прошёл (`no screenshot targets found`).
Переподключение JavaScript-среды проблему FL не устранило.

Симптомы совпадают с открытым
[отчётом о сбое на Windows 10](https://github.com/openai/codex/issues/35446).
Автор отчёта связывает его с ожиданием SoftwareBitmap-конвертации внутри
FrameArrived. Это правдоподобная гипотеза для данного компьютера, а не
измеренный здесь внутренний стек Codex. Низкоуровневая причина локально
не доказывалась; успешный GDI-захват сам по себе не проверяет Windows WGC.

## Что работает и как проверено

С согласия пользователя выполнен оригинальный локальный скрипт
[capture_fl_visible.py](../tools/capture_fl_visible.py).
Он использует уже установленный Pillow / Windows GDI и сохраняет только
область видимого окна FL. Скачивания и установки ПО не потребовалось.

Три настоящих снимка 1830 × 1412 просмотрены:

1. Playlist до действия.
2. Микшер после F9 через штатный `sky.press_key`.
3. Playlist после второго F9 через штатный `sky.press_key`.

Во всех трёх случаях процесс захвата завершился успешно. Микшер виден на
втором снимке и скрыт на третьем. Темп оставался 140 BPM; параметры звука,
MIDI, маршрутизация и проект не редактировались. Свежего аудиорендера нет.

Метаданные и хеши: [CAPTURE_WORKAROUND_STATUS.json](CAPTURE_WORKAROUND_STATUS.json).
Сами диагностические изображения остаются в локальной `local-status`.

## Использование

В текущем рабочем месте скрипт расположен в
`local-fl-matching/tools/capture_fl_visible.py`.
Репозиторная копия может использоваться на месте: корень для выходных файлов
скрипт определяет как родитель каталога `tools`.

Сначала заново получить единственное окно FL64.exe через
`sky.list_windows()` и `sky.get_window()`, затем активировать его.
Идентификатор окна нельзя брать из старого отчёта после перезапуска FL.

Из соответствующего корня:

```powershell
python .\tools\capture_fl_visible.py --hwnd <текущий-id-из-sky> --output .\local-status\FL.png --wait-foreground 25
```

Скрипт проверяет, что HWND действителен, окно не свёрнуто, процесс —
FL64.exe и целевое окно находится на переднем плане. Если другое окно
получит фокус до или во время захвата, PNG не сохраняется. Выходной путь
ограничен рабочим корнем; клавиатуру и мышь скрипт не использует.

Это захват видимой области рабочего стола: FL должна оставаться видимой
и не перекрываться другими окнами. Прочие приложения и отдельные модальные
окна этим испытанием не проверены. Штатные координатные клики Computer Use
также пока не проверены. Нельзя передавать координаты из GDI-снимка как
`screenshotId` штатного Computer Use.

Следующий этап по звуку остаётся прежним: создать отдельный тестовый FLP,
загрузить текущую цепочку и получить свежий локальный WAV по
[FL_STUDIO_RU.md](../../after-DSP-arrival/checkpoint-WIP/FL_STUDIO_RU.md).
