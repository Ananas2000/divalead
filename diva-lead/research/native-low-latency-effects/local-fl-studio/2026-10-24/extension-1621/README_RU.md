## Точные состояния и воспроизведение

`OPPOSED_CANDIDATE.bin` — лучший из новых исследовательских вариантов, **не принятый**. От принятого ZL23 меняет только:

- TargetGain16: 15.11→15.61dB;
- TargetGain17: 15.73→16.23dB;
- Mid AllPass Freq19: 3023.5→3053.7Hz.

Реальный компонент вновь загружен в свежий VST3 процесс: повторное сохранение побайтно идентично; повторный выход первого входа побайтно совпал (max_abs_error0). Это подтверждает воспроизводимость, **но не достаточность улучшения**. `REPLAY_PROOF.json`, `OPPOSED_RESAVED610.tsv` и все native saved components включены в архив отчётов.

`JOINT_CANDIDATE.bin`, `PHASE_CANDIDATE.bin`, `DETECTOR_CANDIDATE.bin` — также исследовательские/отвергнутые состояния. Последний даже хуже контроля. Не загружать их как лучший и не переименовывать в ZL24. FLP рядом с ними собраны из неизменённого исходного FL20 графа заменой только компонента ZL; в GUI они не открывались и не заменяют подтверждённый полный GUI FLP.

Подготовлен `CAPTURE_NATIVE_ONLY.flp` с точным bypass-компонентом ZL. Для него использован **стандартный VST3 Bypass ID1652125811**, normalized1. У ZL есть ещё UI power ID224729667: он отображает On при normalized0, поэтому эти два параметра нельзя путать. В реальном C host bypass-компонент после сохранения и загрузки в свежий процесс возвращает вход побайтно (max_error0). Сам capture FLP **ещё требует GUI проверки**: открыть его в FL, экспортировать float32/48k, проверить, что это pre-ZL, затем использовать для свежей когорты. Не оставлять его пользователю вместо лучшего проекта.

## Вывод для следующего облачного запуска

Локальный ZL23 устойчив к нескольким очевидным ручным поправкам. Изменения двух почти совпадающих Side динамических полос плохо обусловлены; повторный перебор их TargetGain как независимых величин может тратить расчёты на почти одинаковые звуки. Полезно оптимизировать общую и разностную координаты либо заморозить одну полосу на время поиска и обязательно вернуть полный сохранённый компонент для validation. Не утверждать, что одну полосу уже можно без потерь удалить.

Не повторять эти28 конфигураций и прежние28 из основного checkpoint. Новая содержательная гипотеза должна менять то, что эти локальные поправки не исправляют: временную работу детекторов или структуру модуляции, с сохранением трёх удерживаемых входных нот/ARP. Отдельные SideFreq/SideQ проверены лишь грубо; отрицательный результат не доказывает отсутствие более тонкого решения. При изменениях источника Diva или Chorus заново создавать целые свежие source/native реализации, сохранять h2p/281 readbacks и проверять actual FL. Не оценивать такую смену по зафиксированному старому prefix.

Для нового принятия всё ещё нужны независимые свежие6 пар и2 холодных запуска, выигрыш>max(.0005,3SEM), точный component roundtrip, полный actual FL WAV и пакет для пользователя. Пограничный `OPPOSED_CANDIDATE` можно оставить как воспроизводимый seed, но он **не является новой принятой базой**.

Использовался уже установленный официальный ZL Equalizer2 v1.4.1 и существующий Windows C host. DLL/лицензии не включены. Компьютерный capture/native WaveShaper проблема отдельно описана в основном handoff; в этой добавочной серии не предпринимались обходы загрузчика или изменения DLL.
