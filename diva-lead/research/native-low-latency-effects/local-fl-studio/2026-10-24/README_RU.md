Noise0, Drift24.8, Pan−39.33, PlateWet1.12. Асимметрию L/R сохранять; не выравнивать каналы по RMS.

Native base06 с принятыми WaveShaper fine bumps/Chorus9 и штатной M/S цепью не менялся. В SOURCE slot Chorus mix фактически **5593/12800**, не округлённое 0.436953125 из x. ZL стоит на SUM после StereoShaper: MinimumPhase, lookahead0, AutoGainOFF; 12 static Peak, 4 AllPass, 6 dynamic Peak. Declared PDC host=0 не означает измеренную нулевую сквозную задержку DAW.

Исходный objective сохранён: `.65*tone+.35*standard+.05*abs(log(ABgain))+20*max(0,peak-.95)^2` плюс одинаковый для всех ZL-only проб tiny native-EQ regularizer. В локальных таблицах последний константный член не добавлялся; сравнивать дельты можно, абсолютные числа с облаком следует сверять с учётом этого. Используются оригинальный WAV, прежние ranking_scales, alignment+819 и фиксированный video edit 176064 frames. Не менять веса/окна под кандидата. Оригинал используется только для анализа и A/B, не для синтеза.

## Технические ограничения и отрицательные результаты

Пересобран настоящий облачный C VST3 host под Windows, работает: load/controller restore оба0, 610 readbacks, render float32, latency0. Python transport `win_vst3_20261024.py` использует queue+reader thread, т.к. Wine/select pipe wrapper не переносим на Windows. Только ASCII relative filenames без пробелов. Длинный путь private component через полный облачный корень не открывался C fopen; копирование в короткое `sessions/2026-10-24/ZL23_CONFIRMED_INPUT.bin` решило проблему.

У ZL методы normalizedParamToPlain/plainParamToNormalized возвращают normalized identity; колонка `plain` не равна физическим dB. Попытка передать туда dB завершилась `ERROR normalized range` ДО нового аудиопрогона. Для физического изменения использовать `text id display`, т.е. штатный getParamValueByString. После исправления реальные состояния заново загружались перед каждым опытом.

Собран corrected-context FL20 native C host с исключением Chorus из 128×512 silent warmup. Но локальный **WaveShaper FL20 CreatePlugInstance возвращает NULL**, после чего старый C loader падает на чтении p->info. Старый ранее работавший executable сейчас падает так же; запуск вне песочницы не помог. FL26 WaveShaper probe запросил host id71 и также не завершил создание. Не обходить защиту плагина, не исправлять DLL. В этой сессии native-host аудио НЕ использовалось для оценок. `experiment_20261024.py` оставлен как неработающий опыт; лог в renders. Для всех новых ZL trials input получен настоящим экспортом GUI FL26, а DSP выполнялся настоящим ZL. Так удалось продолжить подбор без имитации native DSP.

В `verification/NATIVE_SOURCE_WITH_TAIL.wav` публичного ZIP лежит **сырой Diva input с хвостом**, не выход native цепи перед ZL. Не подавать его прямо в ZL вместо PRE_ZL. Старый `local_native_chain.checkpoint()` загружает устаревшие Oct22 states — для ZL23 его не вызывать.

Простой FL20 parser в `cloud_native_fst.py` не разбирает один из новых FL26 event172 layouts. Сохранённые FL26 файлы не правились ради parser. h2p проверялся через уникальный TLV53 рядом с `/*@Meta`, а точный ZL component найден побайтно в raw FLP; отчёт это явно отмечает. Для программного построения использован проверенный исходный FL20 FLP, переносимый вариант также сохранён. GUI финальный FL26 открывается и рендерится.
